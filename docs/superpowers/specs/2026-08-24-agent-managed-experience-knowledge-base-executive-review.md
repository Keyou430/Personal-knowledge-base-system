# Agent 管理的个人知识库升级方案

## 领导审阅版

### 一、项目结论

建议在现有个人知识库系统上进行一次**增量升级**，建设“问答即沉淀、沉淀可复用、重复可治理”的经验知识库。

本方案不推倒重来，保留现有的文档上传、分领域管理、语义检索和智能问答能力，新增由 Agent 驱动的经验整理、去重、合并和版本管理能力。

核心原则是：**AI 负责整理和发现重复，人负责确认和发布。**

---

### 二、为什么现在做

当前系统已经能够“找到资料并回答问题”，但长期使用后会出现三个问题：

1. 有价值的问答停留在聊天记录中，无法转化为可复用经验。
2. 同类经验容易重复记录，知识库会逐渐膨胀、失去秩序。
3. 经验修改缺乏版本记录，难以追溯为什么改变、能否恢复。

本次升级将问答结果转化为结构化经验卡片，使个人知识库从“资料存放和问答工具”升级为“持续积累和治理的知识资产”。

---

### 三、建设目标

用户在问答中发现有价值内容时，点击“沉淀为经验”，系统即可：

- 调用云端大模型，将当前问题、回答和必要引用整理成经验卡片；
- 自动生成标题、适用场景、核心结论、操作步骤、标签和来源；
- 在保存前检查是否与已有经验重复或相似；
- 展示相似经验和差异，由用户选择合并、另存或放弃；
- 保存经验来源和版本历史，后续可搜索、归档、恢复和复用。

---

### 四、方案概览

```text
现有问答
   |
   | 用户主动点击“沉淀为经验”
   v
Agent 生成候选卡片
   |
   | 用户编辑确认
   v
本地精确去重 + 语义相似检测
   |
   +--> 无相似内容：保存为新经验
   +--> 有相似内容：合并 / 另存 / 放弃
   v
经验库（可检索、可追溯、可恢复）
```

技术上采用“结构化存储 + 语义索引”双层设计：

- SQLite 保存经验卡片、来源、状态和版本，是唯一事实来源；
- 独立的 Chroma 索引负责相似经验检索，可随时重建；
- 现有文档向量库继续独立运行，不与经验内容混在一起。

---

### 五、主要收益

#### 1. 提升知识复用率

把一次性问答转化为可检索经验，减少重复提问和重复分析。

#### 2. 降低知识维护成本

Agent 自动完成初步归纳、标签生成和相似检测，人工只需审核关键内容。

#### 3. 防止知识库失控膨胀

新经验保存前先进行精确和语义去重，重复内容由用户确认合并。

#### 4. 建立可追溯的知识资产

每条经验保留来源和版本，能够回答“这条结论从哪里来、何时修改、能否恢复”。

#### 5. 控制数据与成本风险

仅在用户主动操作时调用云端 API，只发送当前问答和必要引用，不上传整个知识库。

---

### 六、改造范围

#### 本期建设

- 问答结果增加“沉淀为经验”入口；
- Agent 生成可编辑候选卡片；
- 经验卡片精确去重和语义相似检测；
- 相似经验的合并、另存和放弃；
- 经验来源、版本、归档和恢复；
- 经验库查询和索引重建；
- API、数据库和索引异常的恢复机制；
- 启动优化：首次使用时再加载 Embedding 和向量库。

#### 暂不建设

- 多用户权限和团队协作；
- 后台自动监听文件夹；
- 跨领域自动合并；
- 全量文档覆盖检测；
- 多模型自动路由；
- 无人工确认的自动写入。

---

### 七、重点重构说明

本次不是整体重写，但需要进行三项必要的结构调整：

1. **拆分存储职责**：将经验卡片从现有文档向量库中独立出来，避免两类知识相互污染。
2. **增加业务服务层**：把 Agent 调用、去重和合并从 Streamlit 页面代码中抽离，便于测试和后续扩展。
3. **延迟加载重型组件**：调整现有入口，避免每次打开页面都初始化 Embedding 和 Chroma，改善启动速度。

这些重构都直接服务于本次功能，不涉及无关模块改造。

---

### 八、风险与控制措施

| 风险 | 控制措施 |
|---|---|
| Agent 归纳错误 | 先生成候选，用户编辑确认后才保存 |
| 相似判断误合并 | 展示相似度和字段差异，合并必须人工确认 |
| 云端 API 不稳定 | 超时、有限重试、错误提示和候选保留 |
| 数据写入中断 | SQLite 事务回滚，避免产生半条经验 |
| 语义索引损坏 | SQLite 作为事实来源，索引支持重建 |
| 隐私和成本失控 | 仅主动调用，发送范围可见，不上传整个知识库 |
| 升级影响现有功能 | 保留现有 RAG 接口，新增链路与原文档链路隔离 |

---

### 九、阶段性交付

#### 阶段一：经验沉淀闭环

完成问答沉淀、候选卡片、用户确认、SQLite 存储和来源记录。

#### 阶段二：去重与版本治理

完成精确/语义去重、相似经验审核、合并、版本历史和恢复。

#### 阶段三：经验库运营能力

完成经验库搜索、标签筛选、归档、索引重建和运行状态展示。

每个阶段都可独立验收和使用，不依赖后台自动化能力。

---

### 十、验收标准

1. 用户能从一条问答生成经验候选并编辑后保存。
2. 相同或相似经验不会在无提示的情况下直接新增。
3. 合并前可查看差异，合并后可查看并恢复历史版本。
4. 云端调用仅在用户主动沉淀时发生，发送范围清晰可见。
5. API、数据库或索引异常不会丢失问答、候选或已保存经验。
6. 现有文档上传、领域管理和 RAG 问答继续可用。
7. 应用启动不再因 Embedding/Chroma 初始化而阻塞。

---

### 十一、需要审阅确认的事项

本方案请重点确认以下三点：

1. 是否同意采用“AI 整理 + 人工确认”的知识沉淀原则；
2. 是否同意 SQLite 保存结构化经验、Chroma 仅做语义索引；
3. 是否同意先完成问答沉淀和去重闭环，暂不建设后台自动监听和多用户能力。

以上三点确认后，即可进入实施计划和开发阶段。
